# Harvest Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Mac-side harvester, with a local web page, that copies real photos from user-selected drives, shares and folders into the drop zone: read-only on sources, paced, deduped before sending, durable across restarts.

**Architecture:** One native Node process (`src/harvest/host.ts`, kept alive by launchd) runs a Temporal worker on a new `harvest` queue and an HTTP server on 127.0.0.1:3020. `HarvestWorkflow` scans the selected folders into a Postgres ledger (`harvest_items`), then sends PLANNED photos in batches through a throttle gate, a known-content check and an atomic copy into `dropzone/harvest/<label>/…`. The pipeline containers are unchanged.

**Tech Stack:** TypeScript (ESM, strict) on Node 24, Temporal TS SDK 1.24, Postgres 16 via `pg`, node-pg-migrate, sharp + heic-decode (thumbnails), vitest + testcontainers. No new runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-10-19-harvest-design.md` (parent: `docs/superpowers/specs/2026-10-17-pixel-magic-design.md`). Reference implementation for rules and the EXIF reader, read-only: `/Users/rich/Data/source-code/find-all-images-wt/find_images.py` and its `tests/` (including `tests/exif_fixtures.py`).

## Global Constraints

- **Sources are never modified** (spec H1, §10.1). Every harvester write goes through `GuardedFs` (Task 3); sources are opened only with `O_RDONLY`; no `fs` mutating call takes a source path anywhere in `src/harvest/`.
- **Writes allowed only under** `DATA_DIR/dropzone/harvest/` and `DATA_DIR/harvest-cache/`, plus `~/Library/LaunchAgents/com.pixelmagic.harvester.plist` (install target only).
- **Never overwrite** a drop-zone file; never expose a half-written file under a name without the `.part` suffix.
- **No schedule.** Nothing starts a run except `POST /api/runs` (spec H2, §10.7).
- **Pipeline unchanged** except the index `contents_size_idx` (spec H10). Do not edit migrations 0001–0004.
- **Defaults:** `HARVEST_UI_PORT` 3020 · `HARVEST_MAX_DISK_PCT` 80 · `HARVEST_MAX_PENDING_FILES` 20000 · `HARVEST_MAX_PENDING_BYTES` unset · `HARVEST_MIN_SIZE` 20480 · `HARVEST_MAX_ATTEMPTS` 5 · `HARVEST_THUMB_CACHE_MB` 1024.
- **Constants:** send batch 500 · continue-as-new every 50 send batches · gate re-check 30 s · source re-check 60 s · stall after 10 min, re-check 5 min · 25 consecutive errors pause the run · scan heartbeat every 5 s · tree listing timeout 10 s · `diskutil` timeout 15 s · head hash 64 KiB · hash reads 1 MiB · thumbnails 256 px JPEG · EXIF read ≤ 256 KiB (+ ≤ 64 KiB seek, + ≤ 4 KiB Make value).
- **Privacy:** `test-automation/` is read-only and never committed; nothing derived from it is committed; no corpus content goes to hosted services. Use `git add` with explicit paths only; never add `architecturte/`.
- **Stacks:** tests use only `pmtest_*` compose projects; never `docker compose down -v` on the dev stack; never touch `stock-tracker-*` or `pixel-magic-pixel-magic-1`.
- **Style:** match the existing code (comment density, `make*(deps)` activity factories, zod config with `unsetIfEmpty`, idempotent `UPDATE … WHERE state = <expected>`).
- **Gates per task:** `npm test`, `npm run lint`, `npm run format:check`, `npm run typecheck`, `npm run build`; ≥ 85 % branch coverage on new files.

## Review Focus

1. **exFAT DST shift.** An unchanged file on exFAT reports an mtime exactly 3600 s off after a DST change; a rescan must treat it as the same item, not a new one to hash and send. (Task 3 `sameMtime`; Task 5 `rescan with a 1 h mtime shift reuses the row`.)
2. **Remounted or renamed volume.** Expansion mounted as `/Volumes/Expansion 1`, or Plex as `/Volumes/Plex-1`, must map to the same source and label, so history and the ledger carry over. (Task 4 `remount at a new mount point keeps identity and label`.)
3. **Name collision in the drop zone.** `IMG_1.JPG` and `img_1.jpg` in one source folder, or a re-sent name whose earlier copy is still pending, must land as two files with ` (2)`, never overwrite, and be stable on retry. (Task 7 `case-colliding names get a suffix and never overwrite`.)
4. **Crash after rename, before SENT** — and the pipeline already claimed the file. The retry must mark it SENT, not copy again. (Task 7 `crash after rename is recognised via the files table`.)
5. **The pipeline's empty-folder cleanup racing the harvester's `mkdir`.** A parent folder removed between `mkdir -p` and opening the `.part` must be retried, not failed. (Task 7 `parent removed between mkdir and open is retried`.)
